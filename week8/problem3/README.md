Convert Sorted Array to Binary Search Tree
1. Problem
Дан массив nums, отсортированный по возрастанию.
Надо построить из него BST, причём height-balanced: у каждого узла высоты левого и правого поддеревьев отличаются не больше чем на 1.
Ответов может быть несколько, можно любое.

2. Approach
Чтобы дерево было сбалансированным, корнем надо брать середину массива.
Тогда слева и справа останется примерно поровну элементов. И так рекурсивно
для каждой половины.
Почему это BST? Потому что массив уже отсортирован: все что левее середины, меньше нее -> это левое поддерево;
все что правее, больше -> правое.
Работаю с границами l и r, подмассивы не копирую
1. l > r -> часть пустая, возвращаем null
2. m = l + (r - l) / 2 - середина.
3. Создаём узел nums[m]
4. Левое = build(l, m - 1)
5. Правое = build(m + 1, r)

Трассировка: nums = [-10, -3, 0, 5, 9]
1. Вызов build(0, 4)  -> l, r=0, 4  -> m=2  -> Узел 0    -> Слева build(0,1)         -> Справа build(3,4)         
2. Вызов build(0, 1)  -> l, r=0, 1  -> m=0  -> Узел -10  -> Слева build(0,-1)=null   -> Справа build(1,1)         
3. Вызов build(1, 1)  -> l, r=1, 1  -> m=1  -> Узел -3   -> Слева null               -> Справа null               
4. Вызов build(3, 4)  -> l, r=3, 4  -> m=3  -> Узел 5    -> Слева build(3,2)=null    -> Справа build(4,4)         
5. Вызов build(4, 4)  -> l, r=4, 4  -> m=4  -> Узел 9    -> Слева null               -> Справа null               

Дерево получается такое:
        0
       / \
    -10   5
      \    \
      -3    9
Высоты поддеревьев отличаются максимум на 1 → сбалансировано. 

Сначала подумала вставлю по одному. 
То есть беру первый элемент корнем и вставляю остальные обычной вставкой в BST. 
Но массив отсортирован, поэтому каждый следующий больше предыдущего и уходит вправо. 
Получается палка высотой n. Формально BST, а вот height-balanced нет. Решение неправильное.

3. Time Complexity
O(n)
Каждый элемент становится узлом ровно один раз.
На создание узла и вычисление середины O(1).
Вызовов рекурсии порядка n (по одному на элемент + пустые null вызовы). Меньше n не получится.

4. Space Complexity
O(log n) 
Массив делится пополам на каждом шаге, значит глубина рекурсии = высота сбалансированного дерева = log n.
Сам результат (n узлов) занимает O(n), но выходные данные обычно не считают в дополнительную память.

5. Reflection / Improvement
Можно лучше по времени? Нет, O(n) нижняя граница, потому что нужно создать n узлов.
Что улучшить? Можно сделать итеративную версию со стеком, тогда без рекурсии.
- **Какая сложность достижима?** Время O(n), дополнительная память O(log n).
